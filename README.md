# کار روز (KarRooz) — نسخه ۴.۰ (Recurring Tasks & Unified Work Views)

برنامه تحت‌وب مینیمال، متمرکز و شخصی برای مدیریت تسک‌ها، کارهای تکرارشونده، یادداشت‌ها، تقویم خورشیدی و پروژه‌ها به زبان فارسی با ساختار داده محلی.

---

## راهنمای اجرا (How to Run)

پروژه با استفاده از React 19، Vite، TypeScript و کتابخانه استاندارد محاسبات تقویمی `jalaali-js` پیاده‌سازی شده است.

### پیش‌نیازها
- Node.js نسخه 18 یا بالاتر
- npm

### دستورات اجرایی
```bash
# نصب وابستگی‌ها
npm install

# اجرای سرور توسعه محلی
npm run dev

# بررسی عدم وجود خطای تایپ و لایه لود
npm run lint

# ساخت نسخه پروداکشن
npm run build
```

برنامه روی پورت ۳۰۰۰ در دسترس است.

## قابلیت‌های کارهای تکرارشونده (Recurring Tasks)

### ۱. الگوهای تکرار انعطاف‌پذیر و استاندارد (Patterns)
- **روزانه (Daily)**: هر N روز یک‌بار.
- **هفتگی (Weekly)**: هر N هفته یک‌بار در روزهای انتخابی هفته با مرز هفته‌ای **شنبه** (شنبه تا جمعه).
- **ماهانه (Monthly)**: هر N ماه یک‌بار در روز انتخابی ماه (Anchor Day).
  - مبنای تقویمی: پیش‌فرض **تقویم خورشیدی (جلالی)**، با امکان انتخاب اختیاری **تقویم میلادی**. مبنای تقویمی قانون تکرار مستقل از ترجیح نمایشی فعلی ذخیره می‌شود.
  - سیاست روزهای ناموجود در ماه‌های کوتاه‌تر:
    - **انتقال به آخرین روز معتبر ماه (`last_day`)**: مثلاً روز ۳۱ در ماه‌های ۳۰ روزه پاییز یا اسفند ۲۹/۳۰ روزه به آخرین روز منتقل شده و روز لنگر ۳۱ برای ماه‌های ۶ ماه اول سال حفظ می‌گردد.
    - **صرف‌نظر در ماه‌های کوتاه‌تر (`skip`)**: این نوبت در ماه‌های کوتاه‌تر ثبت نمی‌گردد.

### ۲. تفکیک معماری زنجیره و نوبت‌های تاریخ‌دار (Series vs. Occurrences)
- زنجیره تکرار به عنوان یک هویت مستقل ذخیره می‌شود و نوبت‌ها بر حسب نیاز در بازه‌های دیداری نماها بسط پیدا می‌کنند.
- شناسه‌های پایدار برای هر نوبت (`${seriesId}__${originalDate}`).
- هر نوبت بدون اثرگذاری بر سایر نوبت‌های زنجیره قابل مدیریت است:
  - **تکمیل نوبت**: تغییر وضعیت انجام فقط برای همان تاریخ ذخیره می‌شود.
  - **صرف‌نظر از نوبت (Skip)**: همراه با تاییدیه و گزینه «بازگردانی» (Undo) در پیام شناور.
  - **تغییر زمان‌بندی (Reschedule)**: انتقال یک نوبت به تاریخی دیگر بدون ایجاد تسک تکراری در تاریخ اولیه.
- **محاسبه هوشمند مهلت تحویل (Deadline Offset)**: حفظ فاصله تقویمی بین روز انجام و روز مهلت در تمام نوبت‌های تولیدشده.
- **توقف زنجیره از تاریخ مشخص (`stoppedAt`)**: حفظ سابقه گذشته و توقف تولید نوبت‌ها برای آینده.

### ۳. یکپارچگی در تمام نماها (Multi-View Integration)
- **امروز (Today)**: نمایش نوبت‌های تکراری امروز به همراه نوبت‌های عقب‌افتاده انجام‌نشده گذشته.
- **فهرست و کانبان (List & Kanban)**: افق پیش‌فرض ۹۰ روز آینده همراه با نوار کنترل «نمایش نوبت‌های بیشتر (+۹۰ روز)» و «بررسی نوبت‌های گذشته».
- **تقویم (Calendar)**: بسط پویا بر اساس بازه سلول‌های ماه و نوار هفتگی موبایل.

## قابلیت‌های نماهای یکپارچه کارها (Unified Work Views)

### ۱. معماری ناوبری ۴گانه (Four Primary Navigation Entries)
- **امروز (Today)**: محیط آرام و روزانه، بدون تب‌های سه‌گانه اضافی.
- **همه کارها (All Work)**: شامل سه نمای یکپارچه «فهرست»، «کانبان» و «تقویم» در سطح فراگیر همه پروژه‌ها و اقلام بدون پروژه.
- **پروژه‌ها (Projects)**: فهرست پروژه‌ها همراه با صفحه جزئیات هر پروژه که همان سه نمای «فهرست»، «کانبان» و «تقویم» را برای کارهای همان پروژه ارائه می‌دهد.
- **یادداشت‌ها (Notes)**: فضای اختصاصی برای ثبت، جستجو و مرور یادداشت‌ها و ایده‌ها بر اساس پروژه.

### ۲. نماهای سه‌گانه مشترک (Shared Views: List / Kanban / Calendar)
- **فهرست (List View)**: نمایش تفکیک‌شده تسک‌ها و یادداشت‌ها با بج پروژه، وضعیت کانبان، وضعیت انجام و تاریخ‌ها.
- **کانبان (Kanban View)**: ستون‌های استاندارد («انجام‌نشده»، «در حال انجام»، «انجام‌شده») با منوی تغییر وضعیت، بج پروژه و نمایش یادداشت‌های مرتبط در بخش زیرین.
- **تقویم (Calendar View)**: برنامه‌ریزی ماهانه و هفتگی مبتنی بر `plannedDate` و `dueDate` با بخش ویژه «کارهای بدون تاریخ» در پایین نما.

### ۳. فیلتر چندانتخابی پروژه‌ها در «همه کارها» (Multi-Select Project Filter)
- انتخاب ترکیبی چند پروژه به صورت عضویت گزاره‌ای یا (OR Logic).
- امکان انتخاب گزینه مستقل «بدون پروژه» (`__unassigned__`).
- سوئیچ نمایش پروژه‌های آرشیوشده (به‌صورت پیش‌فرض خاموش).
- چیپ‌های برچسبی قابل حذف تک‌تک (`×`) و دکمه «بازنشانی فیلتر».
- حفظ فیلترها و عبارت جستجو هنگام تعویض بین نماهای فهرست، کانبان و تقویم.

## آزمون‌ها و بررسی‌های انجام‌شده (Verified Checks)

- **بررسی الگوریتم تقویم و تکرار با تست‌های واحد خودکار**:
  - محاسبات کبیسه اسفند ۱۴۰۳ (۳۰ روزه) و ۱۴۰۴ (۲۹ روزه).
  - انتقال روز ۳۱ خورشیدی در ماه‌های مهر تا اسفند با هر دو سیاست `last_day` و `skip`.
  - تولید هفته‌ای با مرز شنبه و چند روز در هفته.
  - انزوای تغییرات نوبت و عدم ایجاد اقلام تکراری یا روح.
- **بررسی چیدمان واکنش‌گرا و طراحی آرام فارسی RTL**:
  - موبایل (۳۹۰px): نوار هفتگی شنبه تا جمعه، دیالوگ‌های متناسب، دکمه‌های کنترلی با اندازه استاندارد لمسی.
  - دسکتاپ: تفکیک ابعاد، پالت ذغالی تیره، فونت وزیرمتن و رعایت اصل Zero-Pill.
- **بررسی ساخت بیلد پروداکشن**:
  - اجرای کامپایل بدون خطا (`npm run build`).

## محدودیت‌های فعلی (Current Limitations)

- یادآورهای صوتی/نوتیفیکیشن آنلاین سیستم‌عامل پیاده‌سازی نشده‌اند.
- ذخیره‌سازی داده‌ها به‌صورت محلی در مرورگر (`localStorage`) است و همگام‌سازی ابری در این فاز فعال نیست.
